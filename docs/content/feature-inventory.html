--- title: Feature inventory description: Every user-facing feature of Mossnote in both templates, with its status, how we checked it and any known limit. ---

This is the complete list of what Mossnote does, built by reading the source code and then using the running app. Use it to find a feature, to see how it differs between templates, and to see what is solid and what has gaps.

How to read it

  • Default and Stardew columns: ● the feature is there, ○ it is not, and a word where it differs.
  • works as described. works, with gaps. works, with a limit you should know. exists in the code, but we could not run it here.
  • Checked says how: Ran means we used it in the running app (web version, in Chromium, unless it says computer version); Code means we read the implementation and the project's own tests describe it, but we did not use it ourselves.
  • Possible improvements are marked . They are not built, and nothing here promises they will be.

Not built, on purpose or not yet

The project's README lists things it will not do: image attachments, imported map images, tag colours, checklists, completion tracking, cloud sync, accounts, rich text, statistics, AI features and plugins. They are decisions, not a backlog. Beyond that list, we noticed these gaps:

  • A way to change a journal's template after it is made.
  • ⌘K working while typing in a note, as the shortcut list already promises.
  • The ignored question state that the changelog mentions.
  • A link from inside the app to these documentation pages.
  • A way to create your own template without editing the source.
